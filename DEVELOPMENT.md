# Development guide — clone and continue

Everything you need to pull Hockey-Tracker onto another machine and keep working.
For the what/why of the architecture, read `README.md` and the root `CLAUDE.md`
first; this file is the how-to-run.

## TL;DR

```bash
git clone <repo-url> Hockey-Tracker
cd Hockey-Tracker
git checkout claude/hockey-tracker-agents-qqy7l6   # the active working branch

# Server (any machine with Python 3.11+)
cd server
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
export APPLE_CLIENT_ID=com.hockeytracker.ios        # required for auth
alembic upgrade head                                 # create/upgrade the SQLite DB
uvicorn app.main:app --reload                        # http://localhost:8000  (/docs)
pytest                                               # 20 tests

# Apple apps (macOS + Xcode only) — from the repo root
brew install xcodegen
xcodegen generate                                    # -> HockeyTracker.xcodeproj
open HockeyTracker.xcodeproj
```

## Prerequisites

| To work on…        | You need                                                             |
| ------------------ | ------------------------------------------------------------------- |
| `server/`          | Python **3.11+** (that's it — SQLite is built in)                    |
| `contract/`        | Python + `pyyaml` (already a server dev dep) to validate the spec    |
| `ios-app/`, `watch-app/` | **macOS with Xcode 15+** and **XcodeGen** (`brew install xcodegen`) |

The Swift apps cannot be built off a Mac. The server + contract run anywhere.

## Server (`server/`)

FastAPI + SQLModel/SQLite, managed by Alembic. See `server/CLAUDE.md` for the
full picture.

```bash
cd server
python -m venv .venv && source .venv/bin/activate   # or your env manager
pip install -e ".[dev]"

export APPLE_CLIENT_ID=com.hockeytracker.ios         # REQUIRED — see Auth below
alembic upgrade head                                  # apply migrations
uvicorn app.main:app --reload                         # serve; Swagger at /docs
pytest                                                # run the test suite
```

- **Database**: defaults to `sqlite:///./hockey.db` (gitignored). Override with
  `HOCKEY_DB_URL` (e.g. a Postgres URL) — nothing else changes.
- **Migrations**: after editing table models in `app/storage.py`, run
  `alembic revision --autogenerate -m "..."`, **review** the generated file in
  `alembic/versions/`, then `alembic upgrade head`. (See `server/CLAUDE.md` for
  the SQLite batch-mode named-constraint gotcha.)

## Contract (`contract/`)

`openapi.yaml` is the single source of truth (currently **v0.4.0**). Validate it:

```bash
python -c "import yaml; yaml.safe_load(open('contract/openapi.yaml'))"   # parses
# richer linting, if installed:  openapi-spec-validator contract/openapi.yaml
```

Only `contract-agent` changes it; every change is versioned in
`contract/CHANGELOG.md`. See `contract/CLAUDE.md`.

## Apple apps (`ios-app/` + `watch-app/`) — macOS only

The iOS and watch apps build as **one paired Xcode project** (the watch app is
embedded in the iOS app so WatchConnectivity works). The project is generated by
XcodeGen from the **root** `project.yml`, which composes each app's own
`targets.yml` fragment.

```bash
# from the repo ROOT (not inside ios-app/ or watch-app/)
brew install xcodegen        # once
xcodegen generate            # -> HockeyTracker.xcodeproj at the repo root
open HockeyTracker.xcodeproj
```

Then, in Xcode:

- Set **`DEVELOPMENT_TEAM`** in the root `project.yml` (or the target's Signing
  settings) to your Apple Developer team id, and re-run `xcodegen generate`.
- Add an **`Assets.xcassets`** with an `AppIcon` to each app before archiving
  (not committed).
- Run the **`HockeyTracker`** scheme (builds the iOS app with the watch embedded)
  or **`HockeyTrackerWatch`** to run the watch app directly.

The generated `.xcodeproj` and `**/Sources/Generated/` are gitignored — the
`project.yml`/`targets.yml` files are the source of truth. Never hand-edit the
`.xcodeproj`.

## Configuration reference

| Variable / setting     | Where            | Purpose                                                            |
| ---------------------- | ---------------- | ---------------------------------------------------------------- |
| `APPLE_CLIENT_ID`      | server env       | Sign in with Apple audience; **must equal the iOS bundle id** `com.hockeytracker.ios`. Server 500s without it. |
| `APPLE_ISSUER`         | server env       | Defaults to `https://appleid.apple.com`.                          |
| `APPLE_JWKS_URL`       | server env       | Defaults to `https://appleid.apple.com/auth/keys`.               |
| `HOCKEY_DB_URL`        | server env       | Database URL; defaults to `sqlite:///./hockey.db`.               |
| `HT_BASE_URL`          | iOS scheme env   | API base URL; defaults to `http://localhost:8000`.               |
| Watch API base URL     | `watch-app` code | Defaults to `http://localhost:8000`.                             |
| `DEVELOPMENT_TEAM`     | root `project.yml` | Apple Developer team id for signing.                            |

**Bundle ids** are paired: iOS `com.hockeytracker.ios`, watch
`com.hockeytracker.watch` (with `WKCompanionAppBundleIdentifier` →
`com.hockeytracker.ios`). Keep the iOS bundle id and `APPLE_CLIENT_ID` in sync.

## How development works here: one agent per bounded context

Each top-level directory is owned by a dedicated Claude Code subagent in
`.claude/agents/` (`contract-agent`, `server-agent`, `ios-agent`, `watch-agent`,
`qa-agent`). The rules (full version in `CLAUDE.md`):

1. **Contract-first** — new features start in `contract/`, then the three sides
   implement independently.
2. **Stay in your lane** — an agent edits only its own directory; the root
   `project.yml` is the one shared, orchestrator-owned composition file.
3. **The contract is the source of truth** — only `contract-agent` changes it.

When continuing in a fresh Claude Code session, this structure is picked up
automatically from `CLAUDE.md` + `.claude/agents/`.
